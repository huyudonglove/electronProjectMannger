# Electron Manager UI 设计系统

## 产品定位

Electron Manager 是面向本地项目的结构化记录工作台，不是传统后台，也不是单纯的数据看板。界面优先帮助用户理解：当前项目记录了什么、哪些事项需要跟进、各版本如何演进，以及工作过程留下了哪些可追溯依据。

视觉方向：Calm Workbench（安静、密度适中、信息有层级）。

## 视觉规则

- 深色工作台是默认主题，浅色主题复用同一组语义 Token。
- 暗色模式使用中性黑灰，亮色模式使用暖白；两种主题都以 `#78461A` 作为唯一品牌主色，不使用蓝色背景、蓝色选中面或蓝色主按钮。
- 编号、状态和分类默认使用普通辅助文字；只有告警、阻塞等异常状态使用语义色圆点。
- 琥珀只表示需要关注，淡灰表示完成或已处理，红色只表示错误或危险；完成态不使用绿色。
- 使用 8px 间距基线；页面间距 24px，卡片内距 16px，紧凑区域内距 12px。
- 卡片圆角 10px，控件圆角 6px，弹窗圆角 14px。
- 页面最多使用三层信息：主内容、操作元信息、关联元信息。
- 重要状态使用徽标；次要信息使用小圆点加文字；关联 ID、来源和版本使用弱化文本。
- 不使用彩色标签堆叠表达所有字段，不让装饰性信息抢过标题和待办内容。

## 页面结构

侧边栏包含三组导航和一个固定底部入口：

1. 工作区：总览、想法、任务、研究、协作。
2. 资料库：文档。
3. 管理：版本、工作记录、约束。
4. 固定底部：知识库和主题切换。

顶部只放当前项目、当前版本、刷新和项目切换。页面内容统一使用：页面标题、上下文说明、主要内容区、空状态。

界面术语保持中性和面向记录：

- 使用“项目记录”“问题记录”“待跟进”“工作记录”等描述内容和状态。
- “协作”特指围绕问题、决策、风险和回复形成的可追溯记录。
- 状态只描述记录本身的生命周期，例如待处理、进行中、已完成、已归档和已过期。

## 页面职责

- 总览：先显示项目名称、记录更新时间、各类记录数量及数据目录；统计数字作为入口和辅助信息，并提供项目记录 Skill 路径及复制使用指令。
- 想法：用于快速收集尚未整理的内容，并保留其所属版本和处理状态。
- 任务：使用看板；任务卡突出标题、状态、优先级线和验收摘要。
- 研究：使用队列；待研究事项优先，已完成研究展示结论、验收信息和关联资料。
- 协作：使用问题收件箱；明确区分“待我回复”“待跟进”“风险与后续”和“版本历史”，完整保留问题、回复、决定及关联记录。
- 版本：呈现版本目标、状态和记录边界，版本切换应联动过滤相关任务、想法、研究、问题、风险与工作记录。
- 工作记录：左侧目录、右侧详情；记录级别、状态、关联任务和版本是元信息，不应压过工作内容与结果。
- 文档与知识库：统一使用资料卡片和详情视图，仅在来源和操作上区分。
- 约束：项目长期规则和系统规则分层展示，系统规则只读。

## 组件边界

当前已拆分的布局与基础组件只负责视觉和交互状态，不读取项目数据：

- `AppSidebar`
- `AppTopbar`
- `UiTag`

当前已拆分的业务视图负责对应页面的数据组合：

- `OverviewView`
- `TaskBoardView`

其他业务区域目前仍由 `App.vue` 组合。后续拆分时，基础组件不得依赖 `Dashboard`、项目路径或具体记录类型；业务视图不得重复定义按钮、徽标、卡片和空状态样式。

## 改造原则

- 保持项目记录 IPC、数据结构和业务行为一致，先改表现层。
- 先 Token 和基础组件，再拆页面，最后删除旧样式。
- 每完成一个页面都运行构建，并检查深色、浅色、窄窗口和空数据状态。
- 新增 UI 优先复用基础组件，不在页面中新增同义 CSS 类。
