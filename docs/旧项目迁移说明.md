# 旧项目迁移说明

Telance Records 当前只提供项目记录功能，不包含 Agent 执行、任务树委派、模型配置、Run 检查点或审批流程。旧项目的业务记录不会在运行时被自动改写；迁移应先备份，再把记录无损放入当前目录，最后重建派生摘要。

## 当前记录结构

当前项目数据目录的主要结构如下：

```text
<项目数据目录>/
  project.json
  record-summary.json
  record-counters.json
  index.json
  metadata/
    数据层规范.md
    当前项目基线.md
    需求变更索引.md
  skills/
    project-records/
      SKILL.md
  constraints/
    项目约束.md
  documents/
    Wxxx-*.md
  versions/
    版本索引.md
    Vxxx/
      工程任务.md
      想法与问题.md
      研究.md
      待确认事项.md
      风险与后续.md
      工作记录/
        YYYY-MM.md
```

全局知识仍位于 Telance Records 数据根目录的 `knowledge/`，不属于单个项目数据目录。

## 迁移原则

- 先复制、后验证、最后清理；不要直接在唯一一份旧数据上修改。
- 历史 Markdown 是审计记录。已完成版本的原文、字段、标题、时间和记录顺序应保持不变。
- 不要把旧的 `agent-brief.json`、`index.json`、当前基线或 `record-counters.json` 当作主数据迁移；它们都是派生文件或计数状态。
- 记录引用不表示所有权。迁移或删除某条记录时，不级联删除它引用的文档、知识或其他记录。
- 新写入的工作记录使用 `type:: work-log`。历史文件中的旧类型和值可以原样保留，不需要全局替换。
- 任务树的父子关系、上下文、委派、节点消息、完成汇报和验收报告不属于当前数据模型。历史版本可保留这些原文字段；需要继续编辑的活动任务应另建一张当前格式的独立任务卡，并用普通引用说明来源。

## 迁移步骤

### 1. 停止写入并备份

退出 Telance Records，完整复制以下内容到独立备份目录：

- Telance Records 数据根目录中的 `projects.json`、目标项目数据目录和共享 `knowledge/`。
- 源码项目中的 `.agent-collaboration.md`（如果存在）和当前 `.gitignore`。
- 旧 Agent 运行目录（如果存在且仍需审计），例如数据根目录下的 `agent/`。

备份完成后，记录源目录的文件清单和校验值。macOS 可使用：

```bash
find "<旧项目数据目录>" -type f -print0 | sort -z | xargs -0 shasum -a 256 > old-project.sha256
```

校验文件应保存在旧项目数据目录之外。

### 2. 初始化或确认目标项目

在当前版本 Telance Records 中初始化目标项目，确认已经生成 `metadata/`、`versions/V001/`、`skills/project-records/SKILL.md`、`record-summary.json` 和 `index.json`。

如果沿用原项目数据目录，先确认 `project.json` 中的 `projectRoot`、`dataRoot` 和 `currentVersionId` 指向正确位置。不要用另一个项目的 `project.json` 覆盖它。

### 3. 无损迁移需求变更索引

旧路径是：

```text
collaboration/需求变更索引.md
```

当前路径是：

```text
metadata/需求变更索引.md
```

按以下规则处理：

1. 目标文件不存在时，直接复制旧文件到新路径，保持字节内容不变。
2. 目标文件只有初始化模板、没有实际记录时，先备份模板，再用旧文件完整替换目标文件。
3. 新旧文件都含实际记录时，不要覆盖任一文件。先保存两份原始副本，再把旧文件中的每个完整 Markdown 记录块复制到目标文件；保留原 ID、正文、时间和引用，只按当前聚合文件规则调整记录块顺序。
4. 合并后逐条核对旧文件中的记录 ID 和正文均能在新文件中找到。
5. 在全部验证完成前保留旧 `collaboration/需求变更索引.md`。确认无损后再删除旧路径，避免应用中长期存在两个权威索引。

如果要求严格验证未合并场景，可比较复制前后的校验值：

```bash
shasum -a 256 "<旧项目数据目录>/collaboration/需求变更索引.md"
shasum -a 256 "<目标项目数据目录>/metadata/需求变更索引.md"
```

### 4. 迁移记录 Markdown

按记录语义复制，不按旧界面名称猜测：

- 任务、想法、研究、问题、风险 → 对应 `versions/Vxxx/` 聚合文件。
- 工作记录 → 对应版本的 `工作记录/YYYY-MM.md`。
- 项目约束 → `constraints/项目约束.md`。
- 项目文档 → `documents/`。
- 全局知识 → 数据根目录的 `knowledge/`。
- 版本索引 → `versions/版本索引.md`。

迁移历史版本时，优先整体复制该 `Vxxx/` 目录并保留原文。不要为了符合当前模板而批量重写已完成版本。

仍需继续维护的活动记录可以复制到当前版本并整理为当前字段，但必须同时做到：

- 保留旧记录的完整原文副本。
- 保留原短 ID 或写明来源 ID，避免失去引用关系。
- 不把任务树字段继续写入新的任务卡。
- 不把旧 Run 状态、模型消息或审批状态转换成任务状态。
- 不覆盖同 ID 的现有记录；发生冲突时先人工确定新 ID 和引用关系。

### 5. 清理旧 Agent 生成物

以下文件属于已移除功能的生成物，不是业务记录：

```text
<项目数据目录>/agent-brief.json
<项目数据目录>/collaboration/Agent 同步交接.md
<项目数据目录>/skills/project-collaboration/SKILL.md
<源码项目>/.agent-collaboration.md
```

当前 `updateProjectMetadata` 流程会删除这些明确路径，并从 `.gitignore` 中移除完全匹配的 `.agent-collaboration.md` 条目。迁移时仍应在清理前确认备份存在，并检查 `.gitignore` 的其他行没有变化。

当前版本随后会生成新的 `skills/project-records/SKILL.md`。它只描述记录读写规则，不应从旧 `project-collaboration` Skill 复制模型、运行、审批、任务树或委派说明。

旧数据根目录下的 `agent/` 可能包含设置、对话、运行数据库或输出文件。它不参与纯记录架构，也不会被项目记录迁移自动删除。需要保留审计材料时先整体归档；确认不再需要后再单独清理，禁止把整个应用数据根目录作为递归删除目标。

清理旧生成物时不要删除：

- `versions/` 中的历史 Markdown。
- `documents/`、`knowledge/` 或 `constraints/` 中的业务内容。
- 为审计保留的旧数据备份。

### 6. 重建中性摘要

旧 `agent-brief.json` 不应重命名为 `record-summary.json`。两者契约不同。

迁移业务 Markdown 后，在 Telance Records 中重新打开项目或执行项目元数据刷新，使系统重新生成：

- `record-summary.json`
- `index.json`
- `metadata/当前项目基线.md`
- 必要的 `record-counters.json` 计数状态
- `skills/project-records/SKILL.md`

新的 `record-summary.json` 应只包含项目路径、当前版本、`currentDataPaths`、`recordSkillPath` 和活动记录摘要，不应包含 `instructions`、旧 `skillPath`、模型配置、Run 状态或任务树上下文。

不要手工降低 `record-counters.json` 中的计数。迁移后新建记录的短 ID 必须大于该类型已使用过的最大编号，删除过的编号也不应复用。

## 验证清单

完成迁移后逐项检查：

1. `project.json` 指向正确的源码项目和项目数据目录。
2. `metadata/需求变更索引.md` 包含旧索引的全部记录；原文副本或备份仍可校验。
3. Dashboard 中项目、版本、任务、想法、研究、问题、风险、约束、文档、知识和工作记录数量符合预期。
4. 已完成版本仍可读取，历史 Markdown 没有被格式化或批量改写。
5. `record-summary.json.currentDataPaths` 全部指向当前 `Vxxx` 下的真实文件。
6. `record-summary.json.recordSkillPath` 指向新的 `skills/project-records/SKILL.md`，且不含执行指令、旧 `skillPath`、Run 信息或任务树字段。
7. 新建并删除一条临时记录后，确认既有记录未变化，且下一个短 ID 不复用历史编号。
8. 旧 Agent 生成文件和源码项目指针已清理，`.gitignore` 的其他规则完整保留。
9. 项目数据目录中不存在两个同时使用的需求变更索引。
10. 保留迁移前备份，至少到用户完成一次人工抽查和一次应用重启验证之后。

仓库维护者还应运行：

```bash
pnpm --filter @telance-records/project-core test
pnpm --filter @telance-records/project-core build
node scripts/smoke-test.mjs
```

全部通过后，再把迁移后的目录作为新的权威记录源。

## 不继续使用旧数据

如果旧记录不再需要，可以直接初始化新项目。仍建议先归档旧项目数据目录，再从 Telance Records 的项目列表移除旧项目；移除项目索引不等于删除备份文件。
