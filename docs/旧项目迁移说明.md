# 旧项目迁移说明

Electron Manager 不在运行时自动迁移或修复旧项目数据。打开项目、查看 Dashboard、刷新引导都不会改写已有 Markdown。

## 新项目

直接通过 Electron Manager 初始化。初始化会创建当前版本的完整目录、模板和派生文件，不需要执行迁移步骤。

## 旧项目

只有需要继续使用旧数据时才迁移，建议按下面步骤手动处理：

1. 先备份旧项目管理数据目录。
2. 在 Electron Manager 中初始化一个新项目，得到当前结构和模板。
3. 按内容复制到新项目：
   - 任务、想法、研究、问题、风险、工作记录 → `versions/V001/` 对应文件。
   - 项目文档 → `documents/`。
   - 全局知识 → 管理数据根目录的 `knowledge/`。
4. 按当前模板整理字段：
   - 任务保留 `### 用户原话`，把旧的 `### Agent 理解` 和 `### 执行范围` 合并为 `### 执行定义`，继续保留 `### 验收`。
   - deep 任务补充 `depth_reason:: architecture | migration | cross_system | security | irreversible | decision`、`### 关键约束` 和 `### 方案与回退`；light/standard 删除这些深度字段。
   - 关联任务的日志把旧“产出”和“验收结果”合并为 `### 结果`，保留 `### 修改文件`、`### 验证`。
   - 仍有效的“已知风险”和“后续事项”迁移为独立 `Rxxx`，在日志结果中引用编号，不保留重复正文。
   - deep 日志只保留执行中实际形成或改变的 `### 关键判断`；light/standard 删除旧的用户原话、需求理解、验收标准、关键步骤和执行动作等重复章节。
   - `task_short_id:: T000` 的即时 light 日志额外保留 `### 用户目标`。
   - 研究继续使用 `mode:: breadth | depth`，问题继续保留 `origin::` 和 `### 对话记录`。任务与关联日志的等级必须一致。
5. 重新打开或刷新项目，确认 Dashboard、Agent brief 和当前版本路径正常。

不要直接复制旧的 `agent-brief.json`、`index.json`、基线或 `record-counters.json`；这些文件由当前项目初始化和后续写入重新生成。旧格式只需保留原文时，也可以先作为文档放入 `documents/`，再逐条整理为当前记录。

如果旧数据不再需要，直接初始化新项目即可，无需迁移。
