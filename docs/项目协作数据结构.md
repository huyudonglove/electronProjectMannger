# 项目记录数据结构

Telance Records 是本地优先的项目记录工具。Markdown 保存可读、可追溯的业务记录；JSON 只保存项目配置、稳定编号计数器和可重新生成的导航摘要。应用不执行任务，也不保存模型、运行、审批或委派状态。

## 存储结构

```text
<manager-data-root>/
  projects.json
  knowledge/
    Kxxx-*.md
  projects/<project-id>/
    project.json
    record-summary.json
    record-counters.json
    index.json
    metadata/
      数据层规范.md
      当前项目基线.md
      需求变更索引.md
    skills/
      project-records/
        SKILL.md
    constraints/
      项目约束.md
    documents/
      Wxxx-*.md
    versions/
      版本索引.md
      V001/
        工程任务.md
        想法与问题.md
        研究.md
        待确认事项.md
        风险与后续.md
        工作记录/
          YYYY-MM.md
```

源码项目目录不保存指针、运行数据或派生元数据。管理数据根目录由 Electron 的应用数据目录决定，具体项目位置记录在 `projects.json` 和对应的 `project.json` 中。

## 主数据与派生数据

- `project.json` 保存项目 ID、名称、源码目录、数据目录、当前版本和 schema 版本。
- `versions/`、`documents/`、`constraints/` 与全局 `knowledge/` 中的 Markdown 是记录主数据。
- `record-counters.json` 保存各类短 ID 的最大编号；删除记录后编号不复用。
- `record-summary.json` 是当前项目的导航摘要，提供当前版本路径、活跃记录和最近工作记录。
- `index.json` 与 `metadata/当前项目基线.md` 是根据 Markdown 重新生成的概览。
- `metadata/数据层规范.md` 描述当前记录格式；`metadata/需求变更索引.md` 保存需求变化及相关记录编号。
- `skills/project-records/SKILL.md` 是提供给 Agent 的项目记录规则，由应用按当前结构生成。

派生文件不得作为唯一事实来源。重新生成摘要不会修改任务、想法、研究、问题、风险、文档、知识或工作记录正文。

## 版本边界

- `versions/Vxxx/` 是任务、想法、研究、问题、风险和工作记录的物理边界。
- 当前版本由 `project.json.currentVersionId` 指定；新记录写入该版本。
- `record-summary.json.currentDataPaths` 给出当前版本各类聚合文件的绝对路径。
- 已完成版本保留为历史记录，默认不接收新记录。
- 项目文档、项目约束和共享知识不受当前版本目录限制；它们的 `version` 字段只表示来源。
- 同一时刻只保留一个 active 版本；创建新版本时，旧 active 版本转为 completed。

## 记录类型

| 类型 | 短 ID | 存储位置 | 用途 |
| --- | --- | --- | --- |
| 任务 | `Txxx` | `versions/Vxxx/工程任务.md` | 目标、执行定义、验收和状态 |
| 想法 | `Ixxx` | `versions/Vxxx/想法与问题.md` | 原始想法及后续回答 |
| 研究 | `Dxxx` | `versions/Vxxx/研究.md` | 研究请求、过程、结果和引用 |
| 问题 | `Qxxx` | `versions/Vxxx/待确认事项.md` | 决策、澄清和阻塞事项 |
| 风险 | `Rxxx` | `versions/Vxxx/风险与后续.md` | 风险、验证缺口和后续事项 |
| 工作记录 | `Lxxx` | `versions/Vxxx/工作记录/YYYY-MM.md` | 结果、修改文件、验证和关键判断 |
| 约束 | `Cxxx` | `constraints/项目约束.md` | 项目级长期规则和边界 |
| 文档 | `Wxxx` | `documents/` | 项目内长期资料 |
| 知识 | `Kxxx` | `<manager-data-root>/knowledge/` | 跨项目复用的稳定知识 |
| 版本 | `Vxxx` | `versions/版本索引.md` | 版本目标、成果和后续范围 |

记录之间通过短 ID 或路径建立非拥有型引用。删除一条记录不会级联删除其关联记录。

## 状态与等级

任务状态：

- `todo`：待处理。
- `doing`：处理中。
- `done`：已完成。
- `abandoned`：不再继续。

研究状态使用 `pending | doing | done | archived`；研究模式使用 `breadth | depth`。新建研究只保存 D 记录，不会自动执行研究，也不会自动创建 W 文档或 L 工作记录。

问题状态：

- `open`：仍待答复或澄清。
- `decided`：已经形成决定，仍有后续需要落实。
- `resolved`：问题及相关后续已完成。
- `expired`：问题已被替代或不再适用。

问题回复追加到对话历史，不覆盖旧消息。当前新记录只使用 `user` 和 `system` 角色；旧标签仅在读取历史记录时兼容。

风险状态使用 `open | resolved | expired`，类型使用 `risk | verification | follow-up`。

任务和工作记录可使用 `light | standard | deep`：

- `light`：局部、明确、易回退。
- `standard`：包含多个相关步骤，但方案清楚且风险可控。
- `deep`：涉及架构、迁移、跨系统、安全、不可逆操作或高影响决策。

deep 任务需要一个 `depth_reason`，取值为 `architecture | migration | cross_system | security | irreversible | decision`，并记录关键约束和方案与回退。`priority` 表示紧急程度，与工作等级无关。

## 写入规则

- 版本内记录必须包含 `version:: Vxxx`。
- 聚合 Markdown 中的记录按短 ID 倒序保存。
- 聚合文件写入按文件串行化，并通过同目录临时文件原子替换。
- 持久计数器确保删除记录后不复用短 ID。
- 工作记录使用 `type:: work-log` 和 `record_level:: light | standard | deep`。
- 文档和知识使用独立 Markdown 文件，不与聚合记录混写。
- Markdown 变化后可以重新生成 `record-summary.json`、`index.json` 和当前项目基线。
- 运行时读取不静默改写旧业务 Markdown；格式迁移通过明确的元数据更新流程完成。

## `record-summary.json`

摘要只提供记录导航和当前状态：

- 项目数据目录与全局知识目录；
- 当前版本及其根目录；
- 当前任务、想法、研究、问题、风险和工作记录路径；
- `recordSkillPath` 指向当前生成的项目记录 Skill；
- 活跃任务、研究、问题、风险及最近工作记录。

摘要不包含执行指令、模型配置、任务树、运行检查点、工具调用、审批或委派消息。

## Agent Skill

总览中的“项目记录 Skill”入口用于复制 `recordSkillPath`。

Skill 只约束持久记录的定位、编号、状态、格式和历史保护，不提供模型调用、工具执行、审批、运行状态或任务委派能力。它存放在 Telance Records 数据目录中，源码项目不创建指针文件。

## 旧项目兼容

应用启动时会为已登记项目刷新数据规范、项目基线、索引和记录摘要。新位置不存在时，旧的 `collaboration/需求变更索引.md` 会先无损迁移到 `metadata/需求变更索引.md`，确认新文件写入后再清理旧位置；如果两个位置都已有实际内容，应先按迁移说明人工合并并验证。

旧的运行辅助 Skill 不再生成；当前 `skills/project-records/SKILL.md` 会按纯记录契约重新创建。历史任务、问题、文档和工作记录正文保持原样。详细步骤与验证方式见[旧项目迁移说明](./旧项目迁移说明.md)。
